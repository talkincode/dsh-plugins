# plugins/

本目录承载 `dsh-plugins` 集合的实际插件登记项。**一插件一目录**：每个插件对应一个自包含的子目录，插件的元数据、说明、以及"指向真实实现来源"的信息都放在这里；插件的完整实现代码不要求整包搬进本仓库。

## 约定

- **一插件一目录**：每个插件对应 `plugins/<plugin-id>/`，目录名使用小写短横线命名（kebab-case）。
- **自包含登记**：目录内至少包含一个说明文件（如 `PLUGIN.md` 或 `README.md`），写清楚这个插件是什么、属于哪一类（skill / MCP / 其他）、如何被宿主运行时发现和加载、真正的实现代码在哪（本仓内联代码，或指向外部代码库的链接）。
- **登记优先于搬运**：如果插件的实现已经维护在独立的代码库中，本目录放的是登记/配置说明（指向该代码库、暴露哪些能力），不必把整个实现仓库的源码搬进来。只有当插件本身足够小、天然适合内联维护时，才把完整实现放在这个目录里。
- **不发布到 npm**：新增/修改一个插件登记项，提交合并即生效，不需要打包、发版或上传到任何公共包管理器。
- **脱敏**：任何插件目录下的示例、配置、fixture 都不得包含真实密钥、token、密码、内网地址或客户数据，详见仓库根目录 `AGENTS.md` 的脱敏硬规则。

## 示例结构

```text
plugins/
└── example-plugin/
    ├── PLUGIN.md      # 必需：这个插件是什么、类型、如何加载、实现指向哪里
    ├── scripts/       # 可选：内联实现时的脚本（仅适用于足够小、适合内联的插件）
    └── assets/        # 可选：该插件专用的资源/示例数据（必须脱敏）
```

## 当前状态

本目录目前只有约定说明，尚未包含任何真正落地的插件登记项。新增插件时请遵循上述约定，并同步在 `docs/roadmap.md` 的验收矩阵中登记对应的端到端验证。
